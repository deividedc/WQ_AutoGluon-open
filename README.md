# Automated Machine Learning for Water Quality Prediction  

This repository contains the computational experiments developed for the paper:

> **Campos, D., Galvão, V., Lopes de Rezende, M., Braga, A., Bodini, M., Aires, U. R. V., Yonaba, R., & Goliatt, L.**
> *Automated machine learning achieves accurate water quality prediction with reduced parameter requirements.*
> **Scientific Reports**, 16, 4431 (2026).
> https://doi.org/10.1038/s41598-025-34448-8

The repository is intended to provide the experimental implementation used in the study and to facilitate the reproduction and inspection of the computational experiments reported in the paper.

---

## Repository organization

The experiments are executed through the following sequence:

```text
read_data.py
      ↓
AutoML.py
      ↓
metrics_summary.py
      ↓
analise_de_resultados.py
```

Each script has a specific role in the experimental workflow.

### 1. `read_data.py`

This module is responsible for loading and preprocessing the water-quality dataset.

The preprocessing includes:

* reading the original water-quality data;
* converting the `itemvalue` field to numerical values;
* treating unsuccessful numerical conversions as missing values;
* selecting the variables used in the experiments;
* removing observations with missing values in the selected variables;
* preparing the dataset for the machine-learning experiments.

The variables used as predictors are:

* **EC** — Electrical Conductivity;
* **SS** — Suspended Solids;
* **WT** — Water Temperature;
* **pH** — Hydrogen potential.

The prediction target is:

* **RPI** — River Pollution Index.

The resulting dataset contains **671 complete observations** after preprocessing.

---

### 2. `AutoML.py`

This is the main experimental script.

It uses **AutoGluon Tabular** to automatically train and evaluate multiple regression models.

The experimental procedure consists of:

* splitting the dataset into training and testing subsets;
* executing the experiment repeatedly with different random seeds;
* training the AutoML system under a fixed computational time budget;
* evaluating the trained models on the test data;
* calculating the performance metrics;
* extracting model configurations;
* calculating feature importance;
* saving the experimental results as JSON files.

The experiment consists of **100 executions**, with a maximum training time of **20 minutes per execution** and up to **8 CPU cores**.

The AutoML task is configured as a regression problem using **R²** as the evaluation metric during model selection.

The script evaluates the models generated by AutoGluon, including the models reported in the study, such as:

* CatBoost;
* ExtraTreesMSE;
* KNeighborsDist;
* KNeighborsUnif;
* LightGBM;
* LightGBMLarge;
* LightGBMXT;
* NeuralNetFastAI;
* NeuralNetTorch;
* RandomForestMSE;
* WeightedEnsemble_L2;
* XGBoost.

The exact set of models may depend on the AutoGluon configuration and version used to execute the experiment.

---

### 3. `metrics_summary.py`

This script processes the JSON files generated by the AutoML experiments.

It aggregates the results obtained across the different executions and calculates the corresponding summary statistics for the evaluated models.

The analysis considers the performance metrics used in the study:

* **R** — Pearson correlation coefficient;
* **R²** — coefficient of determination;
* **RMSE** — Root Mean Squared Error;
* **MAE** — Mean Absolute Error;
* **MAPE** — Mean Absolute Percentage Error.

The purpose of this script is to organize the results generated by the individual executions into a form suitable for subsequent analysis.

The numerical results reported in the paper should be consulted in the original publication.

---

### 4. `analysis_of_results.py`

This script performs the subsequent analysis of the experimental results.

It can be used to inspect:

* model performance across executions;
* variability between runs;
* feature importance;
* predictions and observed values;
* residuals;
* statistical properties of the residuals.

The residual analysis reported in the study includes the **Anderson-Darling** and **Kolmogorov-Smirnov** normality tests, using a significance level of **0.05**.

---

# Dataset

The study uses a water-quality monitoring dataset from **Taiwan's national water-quality monitoring system**.

The original dataset contains approximately **36 years of observations**, beginning in 1987, and includes measurements from **306 monitoring stations**.

The original dataset contains **18 variables**. For the experiments reported in the paper, a reduced set of water-quality variables was used.

The selected predictors are:

| Variable | Description             |
| -------- | ----------------------- |
| EC       | Electrical Conductivity |
| SS       | Suspended Solids        |
| WT       | Water Temperature       |
| pH       | Hydrogen potential      |

The target variable is:

| Variable | Description           |
| -------- | --------------------- |
| RPI      | River Pollution Index |

The RPI is used in the study as a proxy for the assessment of water quality.

After preprocessing and removal of observations containing missing values in the selected variables, **671 complete observations** were available for the experiments.

---

# Experimental protocol

The computational experiments described in the paper follow a repeated experimental procedure.

The main settings are:

| Parameter              | Configuration                |
| ---------------------- | ---------------------------- |
| Task                   | Regression                   |
| Target                 | RPI                          |
| Predictors             | EC, SS, WT, pH               |
| Number of executions   | 100                          |
| Maximum training time  | 20 minutes per execution     |
| CPU allocation         | Up to 8 cores                |
| AutoML framework       | AutoGluon Tabular            |
| Model-selection metric | R²                           |
| Evaluation metrics     | R, R², RMSE, MAE, MAPE       |
| Feature importance     | AutoGluon feature importance |

Each execution uses a different random seed in order to evaluate the variability of the AutoML results across repeated experiments.

The repository stores the results of the individual executions so that the aggregated statistics can be reproduced from the generated files.

---

# Feature importance

Feature importance is calculated for the trained models using AutoGluon's feature-importance functionality.

The importance values are also normalized before being stored in the result files.

This allows the relative contribution of the input variables to be inspected across the evaluated models.

The paper discusses the importance of the water-quality variables and reports that **EC** was generally among the most influential predictors, while **WT** tended to have lower importance in the evaluated models.

For the complete interpretation of these results, refer to the original paper.

# Output files

The main AutoML script generates a directory structure similar to:

```text
results/
├── CatBoost/
│   ├── result_run_1.json
│   ├── result_run_2.json
│   └── ...
├── ExtraTreesMSE/
│   ├── result_run_1.json
│   └── ...
├── LightGBM/
│   └── ...
├── XGBoost/
│   └── ...
└── ...
```

A separate directory is also generated for the best model selected in each execution:

```text
results_model_best/
├── result_run_1.json
├── result_run_2.json
├── ...
```

Each JSON file contains information such as:

```text
run
seed
Model
R2
RMSE
MAPE
Best Config
Feature importance
X_test
y_test
y_pred
```

This makes the individual experimental executions available for subsequent analysis without requiring the AutoML experiment to be executed again.

# Reproducing the experiments

After preparing the Python environment, execute the scripts in the following order.

### Step 1 — Prepare the data

Run:

```bash
python read_data.py
```

This module prepares the water-quality dataset for the experiments.

### Step 2 — Run AutoML experiments

Run:

```bash
python AutoML.py
```

This executes the repeated AutoGluon experiments and generates the model-specific JSON result files.

Because the experiment consists of 100 executions with a maximum training time of 20 minutes per execution, the complete experiment may require a substantial amount of computational time.

### Step 3 — Aggregate the metrics

Run:

```bash
python metrics_summary.py
```

This processes the generated JSON files and summarizes the performance metrics across the experimental runs.

### Step 4 — Analyze the results

Run:

```bash
python analise_de_resultados.py
```

This performs the subsequent analysis of the generated experimental results, including model performance, feature importance, predictions, and residual analysis.

# Reproducibility considerations

The repository is provided as an open collection of computational experiments associated with the published study.

The intended workflow is to reproduce the experimental procedure rather than to provide a second presentation of the scientific results. Consequently, the numerical results and their detailed interpretation should be obtained from the original paper.

Several aspects should be considered when reproducing the experiments:

1. **Software versions matter.** AutoML frameworks can change their model implementations, default hyperparameters, available models, and internal behavior between versions.

2. **Randomness is present.** The experiment uses multiple executions with different random seeds to characterize variability across runs.

3. **AutoML model selection is configuration-dependent.** The models generated by AutoGluon may depend on the installed version and execution environment.

4. **Computational resources can affect execution.** Differences in CPU availability and system configuration may affect training time and, consequently, the models explored within the imposed time budget.

5. **The repository should be interpreted together with the paper.** The paper provides the scientific methodology, dataset description, experimental design, and reported results, while this repository provides the computational implementation used to conduct the experiments.
